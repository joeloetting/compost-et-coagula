*This page is a demonstration of the technical layout. The design ideas and code below are generic illustrations written for this fixture. They do not describe how Deftere is, or will be, implemented.*

Most note-taking tools are organized around documents: a file is created, edited, and filed. A research assistant organized around **questions** would make a different object primary. This fixture sketches what that might mean, so that the site's handling of technical material can be tested.

## A question as a first-class object

In a question-centered design, a question carries its own state. It might be open, revised, or closed, and it can point to the evidence that bears on it. The `status` field below is the simplest possible version of that idea.[^status]

```ts
type QuestionStatus = 'open' | 'revised' | 'closed';

interface Question {
	id: string;
	text: string;
	status: QuestionStatus;
	/** Identifiers of notes that bear on this question. */
	evidence: string[];
	createdAt: Date;
}

function revise(question: Question, text: string): Question {
	return { ...question, text, status: 'revised' };
}
```

### Comparing two organizing principles

| Aspect | Document-centered | Question-centered |
|---|---|---|
| Primary object | The file or page | The question |
| What changes over time | The text of the document | The status of the question and its evidence |
| Typical navigation | Folders, tags, and search | Open questions and the notes linked to them |
| Risk | Notes accumulate without direction | Questions multiply without being closed |

### Principles for the fixture

1. Keep the reader's own words distinct from quoted sources.
2. Record where every piece of evidence came from.
3. Let questions remain open for as long as they need to.
   - Closing a question should be a deliberate act.
   - A closed question can be reopened.
